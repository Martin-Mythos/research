# 实验计划

## 实验假设
LoopKit 能够通过规格先行、上下文预算、认证授权审查、输入校验和敌对验证等技能，减少 Agent 在多文件项目开发中的“遗忘底层逻辑”“只改路由不改数据层”“破坏不相关组件”等问题。

## 测试环境与依赖配置
选择 Python 3.12 标准库 + pytest，而非 FastAPI，是为了避免网络安装和第三方依赖影响可复现性。MVP 仍保持三层结构：`src/routes`、`src/services`、`src/data`。

## MVP 项目定义
靶场是一个任务管理 API 的可测试内核：用户注册、登录、任务创建、任务列表、任务读取、任务更新。路由层负责 dispatch 与 HTTP 状态码，业务层负责认证和任务序列化，数据层负责内存持久化。

## 实战需求注入设计
注入需求为：为任务 API 增加 HMAC JWT-like bearer token 认证与 owner_id 授权。未授权请求必须返回 401；用户不能读取或修改其他用户任务，跨用户访问返回 404；不得新增第三方依赖。

## 对比基线
原生裸奔 Agent 的理论基线包括：不写 `PROMPT.md`、没有 `IMPLEMENTATION_PLAN.md`、没有授权专项技能与 verifier。由于本环境不能运行多个真实 LLM Agent 回合并计费，本研究以真实 MVP 实现 + 静态触发模拟作为部分复现，对“百分比提升”仅给出基于修改面和失败模式的保守估算。
